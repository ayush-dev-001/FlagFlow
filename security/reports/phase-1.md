## Attack coverage

The only route is `GET /api/health`, so the suite targets the layers every later route sits behind:

- **Malformed bodies:** truncated JSON, non-JSON, 5,000-level nesting and NUL bytes all get a 4xx in the standard error shape, with no stack traces, paths or connection strings.
- **Prototype pollution:** `__proto__` and `constructor.prototype` in a body don't reach `Object.prototype`.
- **Oversized bodies:** 200 KB and 1 MB bodies get 413, including with mixed-case content types.
- **CORS:** foreign origins, `null`, a look-alike subdomain of the dashboard origin and the demo-web origin are never granted. Foreign preflights are refused. `/v1` sends no CORS headers at all.
- **Header handling:** crafted or oversized `x-request-id` values aren't reflected. Helmet headers (CSP, HSTS, nosniff, frame-ancestors) are present and `x-powered-by` is absent.
- **Routing:** path traversal variants and `TRACE` return a JSON 404.
- **Health:** the response shape is exactly `{ status, checks: { postgres, redis } }` with `ok` or `error`. No versions or error text.

## Hardening added this phase

- Env validation rejects JWT secrets under 32 bytes and never echoes values in its errors.
- pino redacts `authorization`, `cookie`, `x-api-key` and `set-cookie`.
- Unexpected errors are logged in full but returned as a generic `INTERNAL_ERROR`.
- Passwords are hashed with bcrypt at cost 12. Seed credentials come only from `.env`, which is generated by `npm run setup:env`.
- Integration tests refuse to truncate any database whose name doesn't end in `_test`.
